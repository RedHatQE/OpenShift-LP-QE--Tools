## 2026-10-13
### Prow Analyzer architecture and security contracts
- Bot settings use a dedicated `PROW_AN__` namespace without legacy aliases;
  deployments must follow the current manifest. CLI configuration remains separate.
- Channel monitoring is fail-closed: an empty channel allow-list monitors nothing
  unless monitoring all joined channels is explicitly enabled.
- Audit requester identities are pseudonymized as `actor_sha256` rather than raw
  IDs (breaking audit-schema change). Responses and backend errors are represented
  by metadata and error categories; SSE debug logs omit payloads.
  HTTP response bodies and MCP error messages are omitted at the analyzer boundary
  before operational logging, retaining the fixed session-recovery marker.
- Tagged unit and integration suites separate the package coverage gate from
  HTTP/concurrency checks; bot command tests run separately from the package gate.
  Make exposes thin local/CI entry points to suite scripts with one shared
  standalone selected-test guard; each suite owns its configuration, build tag and
  package selection.
- Concurrent analyses share an MCP session with distinct per-request correlation
  IDs.
