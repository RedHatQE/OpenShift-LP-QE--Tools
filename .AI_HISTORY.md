# AI History Log
This file records only **major updates and architectural/breaking changes** in
this directory and its sub-directories. Routine fixes, small adjustments, CI

## 2026-10-13
### Bot environment variable naming
- Group ship-help MCP settings under `PROW_AN__MCP__URL__SHIP_HELP`, `PROW_AN__MCP__TOKEN__SHIP_HELP`, `PROW_AN__MCP__SHIP_HELP__DEBUG`, and `PROW_AN__MCP__TIMEOUT_SEC` (timeout in seconds); use `PROW_AN__MONITORED_CHANNELS` and `PROW_AN__ALLOWED_BOT_IDS` for the bot lists. Deployment environments must use these names; no legacy aliases are provided. The `--mcp-timeout` flag, 1,200-second default, timeout behavior, and all CLI configuration (including `MCP_TIMEOUT_SECONDS`) are unchanged.
### Audit data minimization (breaking audit-schema change)
- Pseudonymize the requester identity in the audit trail: the `actor` field is replaced by `actor_sha256` (SHA-256 of the Slack user ID / OS user). Downstream audit consumers must match on the hash, not the raw ID; per-actor correlation and forward-verification (hash a suspected actor, then search) are preserved. SSE debug logging now emits metadata only (per-line/byte counts) and never payload content.
### Atomic MCP request IDs
- JSON-RPC request ids are now per-request atomic (`nextID`), so concurrent analyses over the shared MCP session cannot cross-correlate. Guarded by `-race` concurrency/correlation integration tests.

## 2026-10-07
- Adopt the `PROW_AN__<CATEGORY>__<FIELD>` env-var naming convention for all bot settings — the `PROW_AN__` app prefix plus a `__` category separator (e.g. `PROW_AN__SLACK__BOT_TOKEN`, `PROW_AN__MCP__URL__SHIP_HELP`) (breaking: the deployment manifest and the live environment must follow). `TLS_INSECURE_SKIP_VERIFY`, `MCP_DEBUG`, and `MCP_TIMEOUT_SECONDS` stay unprefixed because the shared `pkg/analyzer` (used by the CLI) reads them.
