### prow-analyzer — unique JSON-RPC request id per MCP request (fix concurrent cross-talk)
- Both `doAnalysis` (`tools/call`) and `initializeSession` (`initialize`) hardcoded their JSON-RPC request `ID` (to `1` and `0` respectively). The Analyzer and its single MCP session are shared across the handler's 5-goroutine semaphore, so concurrent requests over the shared session could receive each other's responses (wrong-job analyses). Added an `atomic.Int64 nextID` counter to the `Analyzer` struct and set `ID: int(a.nextID.Add(1))` on both request builders, so every request (including a session-recovery re-init) gets a distinct id. Unit + integration (race) tests pass; `pkg/...` coverage remains 100%. NOTE: the other half of the root cause — the single shared MCP session — is still outstanding (per-request session/pool + response-vs-build-ID guardrail).
